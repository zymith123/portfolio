Client Onboarding Automation Prototype

A Zapier workflow that turns a new-client intake form into organized Drive folders, a ClickUp project, and a personalized welcome email — with an AI step that triages and summarizes every submission along the way.

Personal project 2026 Zapier · Google Workspace · ClickUp

The problem

Onboarding a new client by hand means the same handful of steps every time: check whether they're already a client, read through their intake form, set up shared folders, create a project and its first tasks, and send a welcome email. Easy to do inconsistently, or forget a step, when it's manual and repeated for every signup.

What I built

  • A 12-field client intake form (contact details, business type, services purchased, project goals, requirements, deadline, preferred communication, target audience) captured through Google Forms.
  • A lookup against an existing Clients sheet by email, feeding a filter that stops the whole run if the submission is a duplicate.
  • An AI step that reads the remaining fields and returns a structured summary: objectives, key requirements, target audience, deadlines, risks, recommended next steps, a priority rating with reasoning, and a list of any missing fields.
  • A branch on that "missing fields" result — a complete submission continues through the full onboarding path; an incomplete one gets a follow-up email listing exactly what's missing instead.
  • For a complete submission: adding the client to the sheet, creating a parent Drive folder with four subfolders (Contracts, Assets, Documents, Deliverables), creating a ClickUp list with four starter tasks (review requirements, verify assets, schedule kickoff, confirm scope), generating and sending a personalized welcome email with a Calendly link, notifying the team on Slack, and logging the run to an audit sheet — writing the Drive and ClickUp links back into the client's row along the way.

Technology

ZapierGoogle Forms Google SheetsGoogle Drive AI by ZapierClickUp GmailSlack

Key technical decisions

  • The duplicate check gates everything. A lookup against the Clients sheet feeds a filter step that stops the Zap immediately on a match, so a re-submission can't create a second folder, project, or task set.
  • One AI step drives the branch. The same AI-by-Zapier step both summarizes the submission for the team and flags missing fields — that output is what the workflow branches on, instead of a separate validation pass.
  • The sheet doubles as a status tracker. The Drive folder link, the ClickUp list link, and an "email sent" flag are all written back into the client's row as the Zap progresses, so the sheet shows exactly how far onboarding has gotten for any client at a glance.

Status

This Zap is fully built and was tested end to end in the Zap editor (see the demo below), but it's kept as an unpublished draft on a free Zapier plan — a few steps use Pro-tier features to publish live, and there's no real client traffic feeding a portfolio sample.
