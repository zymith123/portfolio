Attendance Management System

A web application for managing employee schedules and attendance: admins import schedule and attendance data from CSV files, and admins and employees review attendance history and reports over a chosen date range.

Team project · Vauldex training program 2025 Nuxt 3 · Play Framework (Scala) · PostgreSQL

The problem

Tracking employee attendance against assigned schedules by hand is slow and error-prone: schedules live in spreadsheets, attendance logs come from a separate source, and answering “who was late last month?” means cross-referencing files. The system needed to take the existing CSV exports, store them in one place, and let both administrators and employees see clear attendance history without manual lookups.

What it does

  • Administrators upload employee schedules and attendance records as CSV files in a defined format.
  • The system stores and links that data in PostgreSQL and exposes it through a REST API.
  • Administrators view attendance history for all employees and generate an attendance report for a chosen start and end date.
  • Employees log in and see only their own attendance history for a date range.
  • Access is separated by role: administrator and employee views have different navigation and permitted endpoints.

Key technical decisions

  • CSV as the import format. The source data already existed as spreadsheet exports, so schedule and attendance ingestion was built around uploading and validating CSV files rather than manual data entry.
  • Separate client and API. A Nuxt 3 frontend and a Play (Scala) REST API are deployed independently and communicate over HTTP, keeping the UI and the data layer decoupled.
  • JWT sessions with role separation. Authentication issues a JWT; routes are grouped into administrator and employee scopes, and a Nuxt route middleware guards pages on the client side to match.
  • Slick evolutions for the schema. Database structure is versioned with Play-Slick evolutions so the schema is reproducible across environments.
  • Passwords hashed with bcrypt. Credentials are never stored in plain text.
  • Date-range reporting at the API. Attendance history and reports accept optional start and end parameters so filtering happens in the query, not the browser.

Key functionality

  • Register / login / session / logout with JWT.
  • Admin: upload schedule CSV, upload attendance CSV, list schedules, list employees per schedule.
  • Admin: full attendance history and a date-ranged attendance report.
  • Employee: personal attendance history for a date range.
  • Role-aware navigation (separate admin and employee sidebars) and toast notifications for upload results.
  • Unit tests on the client for upload components, the auth middleware, and the history/report pages.
