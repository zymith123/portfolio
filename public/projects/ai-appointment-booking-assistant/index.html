AI Appointment Booking Assistant Live & tested

A Telegram bot that lets customers book, reschedule and cancel appointments by chatting in plain language — with Google Calendar as the single source of truth and automatic reminders to reduce no-shows.

Personal project Mock client: Bright Smile Dental Clinic, Cebu Make.com · Claude AI · Google Calendar · Telegram

Demo

The problem

Small clinics and service businesses lose bookings to missed calls and slow replies. This assistant handles booking conversations 24/7 without staff involvement.

What it does

  • Natural-language booking — “teeth whitening on Monday at 10am”. It understands English, Filipino and Cebuano.
  • Rescheduling without duplicates — the existing calendar event is moved, not recreated.
  • Double-booking prevention — if a slot is taken, it suggests nearby free times without revealing who booked it.
  • Business rules — opening hours (Mon–Sat, 9:00–18:00), service durations (30/60/90 min) and half-hour slots.
  • Staff blocks time in Google Calendar (for example a lunch break) and the bot respects it immediately.
  • Booking for someone else — ownership is tracked per Telegram chat, not by name.
  • Automatic reminders — day-before and same-day messages on Telegram every morning at 7 AM.
  • Per-chat memory, so follow-ups like “9am” or “move it to Tuesday” work.
  • Graceful errors — friendly fallback replies, so the bot never goes silent.

How it works

Scenario 1 — Booking assistant (instant, triggered by a Telegram webhook):

  • A Telegram message arrives and the chat’s memory is loaded from a Make data store.
  • The next 60 days of the “Appointments” Google Calendar are read through an API call.
  • Claude decides an action — book, reschedule, cancel or reply — and returns structured JSON, which is parsed and saved back to the chat memory.
  • A router then acts on it: book creates a calendar event, reschedule updates the same event, cancel deletes it (each followed by a confirmation), and reply answers questions, asks for missing details or offers alternative slots.

Scenario 2 — Reminders (scheduled daily at 7 AM Manila time):

  • Search today’s and tomorrow’s events, then send same-day and day-before reminders to each customer’s Telegram chat. The chat ID is stored in the event description.

Engineering decisions & challenges

  • Google Calendar is the single source of truth. I moved away from a separate database, so bookings and manual staff edits can never drift out of sync.
  • Consistent date handling. Dates move between the AI output (ISO 8601 with a +08:00 offset), Make date types and the Calendar API, and I fixed the conversions between them.
  • Reliable AI output. The model returns JSON between delimiter markers, so the scenario can parse it robustly even if the model reasons first.
  • Error-handler routes. Calendar or AI failures send a friendly message instead of crashing the scenario.
  • Privacy by design. Customers only see and manage their own bookings.
  • Built for the free plan. About 7–8 operations per message, with daily rather than polling reminders, keeps it within Make’s free tier.

Status

Fully working and tested end to end (see the demo above), running on the Make.com free plan. It was built for a mock dental clinic, so it is a demonstration project rather than a deployment for a real client.
